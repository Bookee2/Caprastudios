What Impeccable can teach us

Impeccable, by Paul Bakaus, is a design skill for AI coding agents. It gives an agent like Claude one skill with 24 commands (animate, polish, audit, quieter…), a set of "don't do this" rules for AI-looking design, and a Rust engine with 61 automatic checks that run with no AI at all. It's Apache-2.0 licensed and very active: the latest commit is from today.

Short versionWhere Animate.css offered building blocks, Impeccable offers judgement, and its motion guidance is the best written-down version I've seen. It confirms most of what we just did. It also suggests three refinements: let colour and opacity feedback survive reduced motion, cap slow reveals at about 0.8 s, and add a very fast speed for press feedback. Beyond motion, it flags our section kickers.

Lessons beyond motion

Product facts vs visual system

PRODUCT.md records who the product is for, its purpose and its voice. DESIGN.md records the visual system. Keeping them separate stops "who it's for" from getting mixed up with "what it looks like". We spread this across BRAND.md, STUDIO-REFRESH.md and others.

Kickers are its one absolute ban

It refuses any label above a heading ("no brief earns it back"). We use the hand-lettered .kicker three times: twice on the home page and once on the motion lab. Ours is a brand device rather than a template habit, but this is the call worth making deliberately.

Style the browser's own parts

Text selection, the text cursor, scrollbars, focus rings and form controls usually ship with browser defaults. We style text selection and focus rings, but not caret-color, scrollbar-color or accent-color. It's a cheap, telling detail.

Defaults with a reason are fine

Hard offset shadows are allowed "only if the world is actually neobrutalist". Our paint-on-a-wall look, with taped posters and flat colour, is such a world. The principle is that a default is fine when the brand chose it. (Its rule against thick coloured side stripes also caught the card style in my own Animate.css brief, so this brief doesn't use them.)

Should we install it?

Possibly, but not yet. It installs into Claude Code with npx impeccable install, which downloads a signed engine binary and adds a hook that runs its checks on every edit. That overlaps with our own skills (kb-motion, the design plugin, your memory notes on AI-made-looking sites). It would also push opinions our brand deliberately breaks, such as the kicker ban. A safer first step is to run only its automatic checks once against dist/ and read the report. I haven't run anything from it; I only read the source.

Recommended next steps

  1. Add --dur-instant (≈120 ms) for press and toggle feedback, and lower --dur-slow to about 0.8 s (calc(var(--dur)*1.75)).
  2. Cap the rise stagger: min(calc(var(--i)*90ms), 360ms).
  3. Refine reduced motion: let opacity, colour and background transitions keep a short fade (around 150 ms), and snap only movement. This takes a few targeted rules rather than one universal rule.
  4. Decide on the kickers: keep them as a brand choice and write that down, or drop them.
  5. Style the remaining browser parts: caret-color, accent-color and scrollbar-color from the palette.
  6. Optional: run Impeccable's automatic checks once against the built site and compare.
